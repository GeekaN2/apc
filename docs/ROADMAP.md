# APC: план переписывания

Новая версия albion-profit-calculator: фронт и бэк в одном репозитории, данные о предметах и рецептах генерируются из [ao-bin-dumps](https://github.com/ao-data/ao-bin-dumps) вместо ручных JSON.

## Стек

| Слой        | Выбор                                    | Комментарий                                                                                     |
| ----------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Монорепо    | pnpm workspaces, Node 24 LTS, TypeScript |                                                                                                 |
| Фронт       | React 19 + Vite, React Router 7          | роутер уже знакомый по скелету                                                                  |
| UI          | HeroUI + Tailwind                        |                                                                                                 |
| Состояние   | Zustand + TanStack Query                 | Zustand: настройки (persist) и UI-состояние; Query: цены с сервера (кэш, дедупликация, refetch) |
| Таблицы     | TanStack Table + TanStack Virtual        | деревья и таблицы на сотни строк                                                                |
| i18n        | i18next                                  | названия предметов из `formatted/items.json`, UI-строки руками                                  |
| API         | Hono + zod                               | типизированный клиент для фронта через Hono RPC                                                 |
| БД          | PostgreSQL + Drizzle                     | локально без Docker: PGlite или портативный Postgres                                            |
| Авторизация | better-auth                              | Discord OAuth + вход по нику/паролю для мигрированных пользователей                             |
| Цены        | свой ingest из NATS (`nats` v2)          | серверы West / East / Europe + приватные серверы                                                |
| Тесты       | Vitest                                   | обязательно для `game-data` и `calc`                                                            |
| Деплой      | systemd/pm2 + Caddy, поддомен beta       | без Docker, как текущий прод                                                                    |

## Структура

```
apps/
  web/        фронт
  api/        HTTP API
  ingest/     NATS → Postgres, cron (средние цены, перевозки)
packages/
  game-data/  парсер дампов → каталог (предметы, рецепты, категории, локализации)
  calc/       формулы профита, чистый TS без UI
  shared/     общие типы и контракт API
```

### 0. Фундамент

### 1. game-data: каталог из дампов ✅

Принцип: модель каталога повторяет модель дампов, без собственных эвристик. Парсер только нормализует формат, а не придумывает структуру.

Как сделано (`packages/game-data`):

- Коммит дампов закреплён в `dumps.json`; `pnpm data:update` двигает его на последний коммит ao-bin-dumps.
- `pnpm data:build` скачивает `items.json`, `formatted/items.json`, `localization.json` этого коммита в `.cache/` (или берёт локальный клон из `AO_BIN_DUMPS_DIR`, если он на том же коммите) и пишет каталог в `generated/`:
    - `items/<раздел дампа>.json` — по предмету на строку, чтобы дифф между патчами читался;
    - `categories.json` — дерево маркетплейса;
    - `names/<locale>.json` — названия предметов и категорий на 15 языках;
    - `meta.json` — коммит дампов и счётчики.
- `generated/` коммитится: фронту и бэку не нужна сеть и 140 МБ дампов, а обновление дампов видно в диффе.
- Market id: `@N` для энчантов, `_EMPTY`/`_FULL` для журналов; сборка падает, если какой-то id не найден в `formatted/items.json`.
- Названия категорий — ключи `@MARKETPLACEGUI_ROLLOUT_SHOPCATEGORY_*` / `SHOPSUBCATEGORY_*` из `localization.json`.
- Раздел `mountskin` пропущен: у скинов нет тира и категории маркета.
- Пока не перенесены: фермерские поля (`harvest`, `grownitem`, `products`) и лут журналов — добавим, когда появятся соответствующие калькуляторы.

Исходный план:

- Зафиксировать коммит ao-bin-dumps (submodule или скрипт загрузки по хешу).
- `pnpm data:build`: `items.json` + `formatted/items.json` → каталог, версия = дата дампов.
- Нормализация, и только она:
    - `@attr` → camelCase, числа и булевы из строк;
    - «объект или массив» → всегда массив (`craftingrequirements`, `craftresource`, `enchantment`);
    - выкинуть неэкономические поля (спеллы, звуки, анимации, статы боя).
- Сохранить исходные сущности как есть:
    - тип предмета по разделу дампа (`weapon`, `equipmentitem`, `simpleitem`, `consumableitem`, `journalitem`, …);
    - `craftingrequirements` — массив всех вариантов рецепта (обычный, с фракционными токенами, с `ARTEFACT_TOKEN_FAVOR`); какой вариант считать, решает `calc` и настройки пользователя, а не парсер;
    - `enchantments` — вложены в базовый предмет, у каждого уровня свои `craftingrequirements` и `upgraderequirements` (руны/души/реликвии);
    - зачарованные ресурсы — отдельные предметы (`T4_METALBAR_LEVEL1`) с `enchantmentLevel`;
    - `craftresource.maxReturnAmount`, `amountCrafted`, `craftingFocus`, `silver`, `itemValue` — как в дампе.
- Дерево категорий — напрямую из `shopcategories` (`shopcategory` → `shopsubcategory` → `shopsubcategory2`, порядок по `@value`) вместо `profitTreeItemsTree.json`.
- Локализация — из `formatted/items.json` (`LocalizedNames` по всем языкам, ключ `UniqueName` с `@N`).
- TS-типы описывают модель дампа; zod-схемы валидируют её при сборке, чтобы изменения формата после патчей ловились сразу.
- Отдавать фронту статикой по чанкам с хешем в имени.
- Иконки пока напрямую с `render.albiononline.com` (lazy loading); позже свой кэш со сжатием, чтобы не ловить 429.

### 2. calc: формулы ✅

Вместо переноса хардкод-таблиц старого кода — один движок крафта поверх рецептов каталога (`packages/calc`):

- `craft()` — доход с налогами рынка, ресурсы с возвратом (не возвращаются ресурсы с `maxReturnAmount=0`), плата станции, журналы; деньги без промежуточных округлений.
- Процент возврата `1 − 1/(1 + бонус)`: бонус города и специализации по `craftingCategory` из `craftingmodifiers.json` (добавлен в game-data), рефайн — по `refiningbonus`, фокус — `ActionFocus.CraftingEfficiency` (0.59).
- Константы экономики — из `gamedata.json` (`generated/game-constants.json`): налоги рынка (`transactiontax` 0.08 без премиума, `setupfee` 0.025), `ItemValueToNutrition` 0.1125, бонус фокуса, `FameGainFactors.CraftItem`. Не в дампах только то, что премиум делит налог пополам.
- Item value для платы станции — `itemValue` продукта, иначе рекурсивно по первому рецепту (хлеб → мука → пшеница).
- Слава крафта для журналов — та же рекурсия по `fameValue`: у сырья он есть (T4 руда 7.5, T8 150), слиток получает славу своего рецепта (T5 = 3 × T5 руда + T4 слиток = 90). Совпадает с ручной таблицей старого кода (22.5 / 90 / 270 / 645 / 1395) на всех тирах и энчантах; явный `fameValue` у `T4_*_LEVEL1..4` перекрывает рекурсию.
- Журнал для предмета — из `famefillingmissions.craftitemfame.validItem`.
- Golden-тесты (`test/golden.test.ts`) сверяют движок с построчной транскрипцией старого кода (`test/legacy/`) на одинаковых ценах: дерево профита, переработка, еда и зелья.

Найденные расхождения со старым приложением (новый код следует дампам):

- опечатки в таблице item value: T5.1 = 62 вместо 64, T7.4 = 2056 вместо 2048;
- округлённые значения артефактов (`T8_rune` 63.5 вместо 64 на материал);
- уровень артефакта считался по позиции в дереве, и королевские вещи сбивали его (`T4_HEAD_CLOTH_HELL` получал relic вместо rune);
- налог рынка брался и с пустого журнала: `(full − empty) × (1 − fee)` вместо `full × (1 − fee) − empty`;
- королевские вещи в игре крафтятся из обычной вещи + сигилы, плащи — из готового плаща + герб + сердца, а не из материалов;
- у инструментов больше нет энчантов, зачарованных каменных блоков в игре нет;
- рыба в рецептах еды имеет item value 1–4, а не 0;
- трансмутации камня: серебро в игре ~10% выше старой таблицы, и у камня появились энчанты с обоими видами трансмутации;
- опечатка в таблице item value трансмутаций: T5.4 = 85.32 вместо 85.34;
- трансмутация с предыдущего энчанта продавалась с налогом 4.5% вместо 6.5%.

Трансмутации (`src/transmutation.ts`): это крафт по `TRANSMUTE`-рецепту, движок списывает `silver` рецепта × `silverFactor`. Глобальную скидку на серебро игра применяет на лету, в дампах её нет, поэтому `calibrateSilverFactor` восстанавливает её по стоимости, увиденной в игре (как калибровка в старом коде). `cheapestTransmutations` ищет самые дешёвые цепочки по графу всех `TRANSMUTE`-рецептов каталога вместо старой сетки «тир × энчант». Таблицы серебра руды, шкур, волокна и дерева совпали с дампами один в один.

Открытые вопросы:

- `destinyAndJournalCraftFameFactor` у экипировки старый код не учитывал, похоже на новую механику игры — разобраться;
- алхимию в игре переделали: у экстрактов нет item value в дампах (старый код брал 40), сейчас считаем 0 — разобраться с новой механикой.

Цех артефактов (`src/artifacts.ts`): в игре больше нет случайной плавки 36/50 фрагментов в артефакт ветки — у каждого артефакта в дампах свой рецепт из 50 фрагментов его типа, поэтому крафт артефакта — обычный `craft()`. Ветка (воин/охотник/маг) выводится из дампов: артефакт → предметы, в которые он идёт → журналы этих предметов. `profitStats` даёт среднее, медиану и разброс по ветке, как в старом экране. Старые списки веток целиком входят в новые; новые сверх них — посохи оборотня и фейская броня (старый код отбрасывал `_FEY`). Появились новые типы фрагментов: `SHARD_CRYSTAL`, `SHARD_FIRE_DRAGON`.

Открытый вопрос: распространяется ли процент возврата на фрагменты при крафте артефакта — в рецепте у них нет `maxreturnamount="0"`, значит по дампам возвращаются; старый код возврат не учитывал. Точного ответа пока нет — по умолчанию следуем дампам, проверить в игре.

Перевозки (`src/transport.ts`): прибыль = продажа в городе назначения за вычетом налогов − покупка в исходном городе, процент, «объём» (прибыль × продаж в день) и новая метрика — прибыль на килограмм груза по весу предмета из дампов (в старом API `BY_MOUNT_PROFIT` был объявлен, но не реализован). `compareTransports` повторяет старую сортировку: сначала свежесть цен, затем выбранная метрика. Маршрут без цены в городе назначения уходит в конец (старый код считал её нулём).

Выбор цены (`src/prices.ts`): `pickSalePrice` берёт свежую сторону рынка (младше суток), иначе ту, что даёт больше серебра после налогов из `game-constants.json`. Старый код сравнивал с множителями 0.97 / 0.955 времён налога 3%, поэтому при отношении buy/sell между 0.974 и 0.985 выбор отличается.

Склейка нескольких записей одного предмета (качества, источники) в одну цену — `mergeQuotes` в `src/prices.ts`, см. этап 3.

### 3. Бэк: цены ✅

Сделано:

- `packages/db`: Drizzle-схема `servers` и `market_orders` (PK `server_id + order_id`, `bigint` для id ордеров), миграции drizzle-kit, запросы `upsertOrders`, `deleteExpiredOrders`, `bestPrices`. Коды рынков из AODP (`0007` Thetford Market, `0301` Thetford Portal, `3003` Black Market…) хранятся как есть, город по коду — таблица `MARKETS`.
- Локальный Postgres без Docker: `pnpm --filter @apc/db db:dev` поднимает PGlite-сервер на 5432, тесты используют PGlite в памяти.
- `apps/ingest`: подписка на `marketorders.deduped.bulk` каждого сервера из БД (West / East / Europe), валидация zod, батчевый upsert, срок жизни ордера ≤ 14 дней (как в старом ingest), чистка истёкших раз в 10 минут, переподключение к недоступному серверу раз в минуту.
- `apps/api`: Hono, `/api/health`, `/api/servers` (без NATS-кредов), `/api/prices?server=&items=&cities=&qualities=` — лучшие цены в форме AODP (`sellPriceMin`/`buyPriceMax` + даты), её понимает `pickSalePrice` из calc. Тип `AppType` для типизированного клиента на фронте.
- Живой прогон: Europe пишет сотни ордеров в минуту, цены отдаются через API.
- Средние цены (`average_prices`): ingest раз в сутки качает из AODP charts API 30 дней истории всех торгуемых market id каталога (~10 300) пачками по ~150 id в запросе с паузой 2 с, ждёт `ratelimit-reset` при 429 (AODP режет клиентов без gzip). Формула как в старом воркере: средняя цена, взвешенная по проданным штукам, качества 1–3, продажи в день по дням с продажами. Старый воркер ходил по одному предмету раз в 5 с — часы на сервер, теперь минуты. Отдаются через `/api/averages`.
- Фильтр «троллинговых» ордеров: `bestPrices` пропускает ордера на продажу дороже средней в 5 раз. В отличие от старого `/data`, ордера на покупку не фильтруются — завышенный ордер на покупку платит настоящее серебро.

- Склейка качеств и источников в одну цену (`mergeQuotes` в calc, для перевозок): каждая сторона рынка отдельно — свежая цена важнее устаревшей, затем более новая на 5 минут, затем лучшая (минимальный ордер на продажу, максимальный на покупку). Для ордеров на продажу совпадает со старым воркером перевозок; старый код сравнивал и ордера на покупку по меньшей цене.

Оптимизация на потом: `best_prices` как материализованная таблица, если выборка из `market_orders` станет медленной.

### 4. Авторизация и миграция ✅

- better-auth 1.7 в `apps/api` (`/api/auth/*`), таблицы `user`, `session`, `account`, `verification` сгенерированы его CLI в `packages/db/src/authSchema.ts`.
- Новые пользователи — только через Discord (регистрация по паролю выключена). У Discord-аккаунтов без email (только телефон) — email-заглушка из Discord id.
- Мигрированные пользователи входят по нику и старому паролю: bcrypt-хеши лежат в `account` как есть, проверка пароля различает bcrypt и scrypt better-auth. Ник — любой непустой, как на старом сайте. Discord привязывается к аккаунту (`allowDifferentEmails`, у старых пользователей email-заглушки `<id>@legacy.invalid`).
- Роли через admin-плагин: `user`, `supporter` (может создавать приватные серверы), `admin`; `tester` стал `user`. Админ-плагин закрывает функции старой админки: список пользователей, смена роли, сброс пароля.
- Свои таблицы: `user_settings` (настройки дерева, `/api/settings/tree`), `server_access` и `servers.owner_id` — приватные серверы видны владельцу и тем, кому дан доступ, в том числе их цены и средние.
- Импорт из Mongo: `pnpm --filter @apc/db db:import-legacy` — пользователи со старыми id, настройки, приватные серверы с доступом по нику; повторный запуск ничего не дублирует, пропущенные записи печатаются с причиной.
- Не переносятся: регистрационные токены, refresh-токены, `testers_history`. Обновление приватных серверов в старом коде не работало (опечатка в имени коллекции `servders`).

Осталось: создать Discord-приложение и прописать `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET`; прогнать импорт на реальной базе.

### 5. Каркас фронта ✅

- Layout: сайдбар с калькуляторами, шапка с выбором сервера, языка, темы и меню пользователя; на главной те же контролы без выбора сервера.
- API с того же origin: Vite проксирует `/api` на `API_URL` (по умолчанию `http://127.0.0.1:4000`), поэтому cookie better-auth первые-сторонние и CORS не нужен. Клиент — `hono/client` с `AppType` из `@apc/api` (только типы) и TanStack Query.
- i18n: i18next, UI-строки en/ru в `apps/web/src/i18n/locales`, типизированные ключи. Язык хранится в Zustand (persist), при первом заходе — язык браузера. У каждого языка указана локаль названий предметов из `game-data` (`en-US`, `ru-RU`) на будущее.
- Сервер: список из `/api/servers` (с приватными серверами вошедшего пользователя), выбор в Zustand; если выбранный сервер пропал из списка — первый доступный.
- Вход: модалка с Discord и входом по нику/паролю для старых аккаунтов (better-auth `usernameClient`). Меню профиля: ник, роль, «Привязать Discord», если он ещё не привязан, выход.

Отложено: язык в URL, как на старом сайте (`/ru/...`), — для SEO и старых ссылок; отдельная страница профиля; мобильная версия сайдбара; код-сплиттинг (бандл ~750 КБ).

### 6. Разделы (по порядку)

1. Переработка ✅: самый простой раздел, на нём обкатываем связку каталог → цены → calc → UI.
    - `calc/src/refining.ts`: рефайненные ресурсы семейства из каталога (T2–T8, у камня без зачарований), рецепт — первый в дампе (остальные варианты с фракционными токенами или зачарованным камнем), расчёт через `craft()`, список market id для запроса цен.
    - Фронт: каталог ресурсов (`simpleitem.json`, модификаторы, константы) грузится только на странице раздела отдельными чанками; цены — `/api/prices` по трём городам (сырьё, ресурс тира ниже, продажа), город переработки даёт бонус. Ресурсы покупаются по минимальному ордеру на продажу, продукт продаётся через `pickSalePrice`.
    - Отличия от старого: нет цены — ячейка «нет цены», а не фейковый профит; премиум — переключатель; T2/T3 тоже считаются; настройки сохраняются; в подсказке ячейки — разбивка расчёта, возраст цен и фокус за крафт.
    - Не перенесено: профит на очко фокуса, журналы.
2. Дерево профита ✅
    - `calc/src/family.ts`: «семейства» предметов (`MAIN_SWORD` во всех тирах) из категорий маркета с экипировкой, уровни зачарования, варианты рецептов из дампа (артефакт или токен авалонской энергии, SET1/2/3 + сигилы у королевских предметов, базовый плащ + `_BP` + сердце у фракционных), расчёт через `craft()` с журналами и списком market id.
    - Навигация по дереву маркета иконками, как в старом дереве: ряды категория → подкатегория → предмет (категорию представляет типичный предмет, подкатегорию — её первый), под ними строка «Оружие › Мечи › Палаш»; названия — из `names/<locale>.json` на языке интерфейса, у городских плащей — названия городов.
    - Настройки: города продажи (в том числе Чёрный рынок), крафта, ресурсов, артефактов и компонентов, журналов; фокус, премиум, налог станции, число крафтов, свой процент возврата, журналы, качества продаваемого предмета (цены качеств склеиваются `mergeQuotes`). У вошедших пользователей синхронизируются с `/api/settings/tree`; старый формат (`useMultipleCities`, `craftFee`, `expert.qualities`…) конвертируется при загрузке, сохраняется уже новый с `version: 2`.
    - В подсказке ячейки — продажи в день из средних за 30 дней.
    - Таблица и контролы настроек общие с переработкой (`ProfitTable`, `SettingsControls`).
    - Не перенесено: средняя цена вместо текущей, профит на очко фокуса.
    - Свои цены (оба раздела): над таблицей строка иконок — продукт и ингредиенты рецепта; клик открывает поповер с полями в раскладке таблицы (тиры × зачарования), в пустом поле — рыночная цена. Точка на иконке — есть свои цены. Хранятся в браузере по серверу и market id, заменяют рыночную при покупке и продаже (как ордер на продажу) в любом городе; в подсказке ячейки помечены «своя». `prices/priceBook.ts` склеивает рыночные и свои цены для обоих разделов.
3. Еда и зелья ✅
    - Те же «семейства» из `calc/src/family.ts`: еда — `consumables/food`, зелья — `consumables/potions` и алкоголь (в дампах он фермерский продукт). Количество за крафт (10 еды, 5 зелий), зачарования с рыбным соусом и экстрактом, невозврат авалонского токена (`maxReturnAmount=0`), item value для налога станции — всё из дампов вместо захардкоженных 40/0/64 и ограничения зелий до .1.
    - Иконками: «Еда / Зелья» → семейство. Настройки: города продажи, готовки и покупки ингредиентов, фокус, премиум, налог станции (800), число крафтов, свой процент возврата; хранятся локально.
